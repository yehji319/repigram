# Repigram 저작권·법률 정리 (운영자용)

> ⚠️ 이 문서는 서비스를 설계하면서 정리한 참고 자료이고, 법률 자문이 아니에요.
> 유료 출시 전에는 변호사(저작권·개인정보 분야)의 검토를 받는 걸 강력히 추천해요.

## 1. 핵심 원칙: "개인 레시피북"으로 유지하기

| 구분 | 저작권 보호 여부 | Repigram 대응 |
|---|---|---|
| 재료 목록, 조리 방법 (사실·아이디어) | 일반적으로 보호 대상이 아님 | AI가 재료·순서로 정리 |
| 설명 문장, 사진, 영상, 썸네일, 자막 (표현) | **보호됨** | 원문 저장 안 함, 다시 쓰도록 지시, 링크로 연결 |
| 회원이 직접 찍은 사진 | 회원 본인 소유 | 비공개 저장 |
| 남의 게시물 캡처 | 원작자 소유 | 개인 보관만, 공유에서 기본 제외 |

- 회원 개인이 보관하는 건 「저작권법」 제30조(사적 이용을 위한 복제) 범위로 볼 여지가 커요.
- 위험이 커지는 순간은 **공개하는 순간**이에요. 공개 피드, 검색 노출, 캡처를 그대로 공유하는 기능은 만들지 않거나 신중하게 만들어야 해요.

## 2. 제품에 이미 반영한 것

- [x] 원본 링크 저장·표시, "원작자에게 저작권이 있어요" 안내 (레시피 상세 화면)
- [x] 유튜브 설명란·영상 원문은 저장하지 않고 AI 정리에만 사용
- [x] AI 지시문: 원문 그대로 베끼지 않고 간결하게 다시 쓰기, 홍보 문구·해시태그 제외
- [x] 유튜브 썸네일은 유튜브 주소로만 표시 (복사해서 저장하지 않음)
- [x] 인스타그램은 링크로 수집하지 않고, 회원이 올린 캡처·붙여 넣은 글만 사용
- [x] 사진 업로드 화면: "직접 찍은 사진이나 개인 보관용 캡처만" 안내
- [x] AI 결과에 "✨ AI 정리" 표시와 "알레르기 재료를 확인하세요" 경고
- [x] 레시피·사진 비공개 저장 (Supabase RLS, 비공개 Storage)
- [x] 이용약관 / 개인정보처리방침 / 저작권 정책·신고 페이지 (초안)
- [x] 로그인 화면에 약관·방침 링크와 동의 안내

## 3. 출시 전에 꼭 할 일

### 문서
- [ ] 세 페이지의 노란색 `[ ]` 칸 채우기: 운영자명, 문의 이메일, 시행일, 개인정보 보호책임자
- [ ] `config.js`의 `CONTACT_EMAIL` 채우기
- [ ] 개인정보처리방침의 Supabase 저장 지역을 실제 리전으로 수정 (서울 `ap-northeast-2` 추천)

### Google 관련
- [ ] Google 로그인 **OAuth 동의 화면** 설정: 앱 이름, 로고, 개인정보처리방침 URL, 이용약관 URL, 승인된 도메인 (repigram.com)
- [ ] **YouTube API 서비스 약관과 개발자 정책** 확인
  - 개인정보처리방침에 YouTube 약관·Google 개인정보처리방침 링크 넣기 (반영함)
  - API 데이터 저장 기간 제한 확인 (현재 원문을 저장하지 않는 구조)
  - 하루 할당량을 늘리려면 Google의 정책 준수 심사(audit)가 필요할 수 있어요
- [ ] Gemini API는 **유료 등급(결제 등록)**으로 사용: 무료 등급은 입력이 Google 제품 개선에 쓰일 수 있어요
- [ ] Gemini의 유튜브 링크 분석은 현재 preview 단계: 가격과 한도가 바뀔 수 있으니 출시 전에 다시 확인

### 법률
- [ ] **인공지능 기본법** (2026년 1월 시행): 생성형 AI를 이용한다는 사실을 미리 알리고 결과물을 표시하는 의무가 있어요. 약관 제6조와 "AI 정리" 배지로 반영했고, 시행령의 세부 기준을 확인해야 해요
- [ ] **개인정보 국외 이전 고지** (개인정보 보호법): 방침 5번에 표로 반영했어요. 업체가 바뀌면 함께 수정해야 해요
- [ ] **유료 구독을 시작할 때**
  - 사업자등록과 통신판매업 신고
  - 사이트 하단에 사업자 정보 표시 (상호, 대표자, 사업자등록번호, 주소, 연락처)
  - 약관 제11조에 결제, 해지, 청약철회, 환불 조항을 구체적으로 작성
  - 앱에서 판매할 때는 Apple과 Google 인앱결제 규칙 적용 (수수료 15~30%)

### 앱스토어
- [ ] **앱 안에서 계정 삭제 기능** 제공: Apple 심사 필수예요. 현재는 이메일 요청 방식이라 앱 출시 전에 버튼으로 구현해야 해요
- [ ] 앱스토어의 개인정보 항목 (Apple 개인정보 라벨, Google Play 데이터 보안 섹션) 작성

## 4. 공유 기능을 만들 때 지킬 규칙

`copyright.html`에 공지한 원칙을 그대로 구현해야 해요.

1. 링크를 받은 사람만 볼 수 있게 하고, 검색 노출은 막기 (`noindex`)
2. 원작자 이름과 원본 링크를 자동으로 크게 표시
3. 캡처 사진은 기본으로 제외하고, 직접 찍은 사진만 회원이 선택해서 포함
4. 공유 화면마다 신고 버튼 두기
5. 신고가 들어오면 바로 비공개 처리하고, 처리 기록 남기기

## 5. 신고 대응 절차 (저작권법상 온라인서비스제공자 절차)

1. 신고 접수 (이메일): 권리자 정보, 침해 위치, 권리 증명을 확인
2. **지체 없이** 해당 공유를 중단하고 신고자와 회원에게 통보
3. 회원이 정당한 권리를 소명하며 재게시를 요청하면 법정 절차에 따라 처리
4. 반복 침해 회원은 이용 제한 또는 계정 해지
5. 모든 처리 기록 보관
